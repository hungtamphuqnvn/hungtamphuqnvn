# Hey, I'm hungtamphuqnvn

I spend most of my time writing Python scripts that quietly do the boring work for me. Whether it's scraping data, orchestrating small workflows, or keeping servers in line, automation is where I feel most at home.

## What I actually work on

Python is my daily driver. I reach for it when I need to glue APIs together, process logs, or build small tools that save hours later. I like keeping scripts short, readable, and easy to extend.

Linux sits underneath almost everything I run. I prefer working close to the metal—bash, systemd, simple monitoring—rather than stacking layers of abstraction I don't need. A clean terminal and a solid set of command-line tools still beat most GUIs for the tasks I care about.

APIs are the connective tissue. I write clients, handle auth, deal with rate limits, and try to make the integration side as boring as possible so the rest of the system can stay interesting.

## How I approach things

I start small. A single script that solves one real problem is better than a framework that solves twenty theoretical ones. Once something works, I clean it up, add logging, and only then think about packaging or sharing.

I also care about the environment the code runs in. Predictable Linux setups, clear environment variables, and scripts that fail loudly when something is wrong make life easier when you come back to a project months later.

## Currently exploring

- Better ways to schedule and monitor long-running Python jobs
- Lightweight API wrappers that stay out of the way
- Small system utilities that remove friction from everyday Linux use

If you work on similar problems—scripting, automation, or just keeping systems tidy—feel free to look around or open an issue. I'm always happy to trade notes on practical approaches.
